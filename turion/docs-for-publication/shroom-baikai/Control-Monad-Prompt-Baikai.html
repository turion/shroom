Description

Builds the Backend that sends a shroom program's requests to a real model, through baikai. Pick the constructor for the host and pass the result to runPromptResultEff:

import Control.Monad.Prompt (prompt)
import Control.Monad.Prompt.Baikai (claudeBackend)
import Control.Monad.Prompt.Effect (context, defaultPromptConfig, runPromptResultEff)

main :: IO ()
main = do
  backend <- claudeBackend apiKey
  result <- runPromptResultEff backend defaultPromptConfig $ do
    context "A spider has eight legs."
    prompt @Int
  print result

The example needs OverloadedStrings and TypeApplications, and apiKey is an Anthropic API key as Text. For another host, replace claudeBackend:

  • claudeBackend is the Claude API.
  • anthropicCompatBackend is any other host that speaks the Anthropic Messages API.
  • localOllamaBackend is a local Ollama server.
  • openAICompatBackend is any other host that speaks the OpenAI Chat Completions API.

All four are built on baikaiBackend, which makes one request per runBackendChat. Calling a tool the model asks for, and sending the result back, is left to the caller as for every backend (see promptTools).

What the four constructors share:

  • Each registers its baikai provider when it runs, so each returns in IO.
  • The base URL of anthropicCompatBackend and openAICompatBackend takes no trailing /v1. The transport appends its own, so one given here would produce /v1/v1/....
  • A reply is limited to 4096 tokens. The context window and output limit set on the Model are the published ones for the model of claudeBackend, and the placeholders 8192 and 4096 for the other constructors, whose model is not known; they do not limit a reply.

Note that other limits need baikaiBackend with a Model and Options of your own.

Backends for common hosts

claudeBackend :: forall (m :: Type -> Type). MonadIO m => Text -> IO (Backend m) Source #

The Claude API at api.anthropic.com, via baikai-claude. Takes an Anthropic API key. The model is claude-haiku-4-5-20251001, with its published limits (200000 tokens of context, 8192 of output) as the Model limits. For another Claude model use anthropicCompatBackend with the base URL https://api.anthropic.com.

anthropicCompatBackend :: forall (m :: Type -> Type). MonadIO m => Text -> Text -> Text -> IO (Backend m) Source #

Any host that speaks the Anthropic Messages API, via baikai-claude. Takes the base URL, the model id and the API key.

Unlike the key of openAICompatBackend, this one is not a Maybe: a hosted Anthropic-compatible host checks a real key, and a local proxy that does not still needs a placeholder, which only the caller can choose. The key is passed on as it is.

localOllamaBackend :: forall (m :: Type -> Type). MonadIO m => Text -> IO (Backend m) Source #

A local Ollama server, through its OpenAI-compatible Chat Completions API, via baikai-openai. Like openAICompatBackend without an API key, for the server at OLLAMA_HOST, read through normaliseOllamaHost; without OLLAMA_HOST it is http://127.0.0.1:11434.

openAICompatBackend :: forall (m :: Type -> Type). MonadIO m => Text -> Text -> Maybe Text -> IO (Backend m) Source #

Any host that speaks the OpenAI Chat Completions API, hosted or self-hosted (vLLM, the llama.cpp server), via baikai-openai. Takes the base URL, the model id and the API key.

The key is a Maybe: Nothing for a host that checks no credential, such as a bare Ollama or llama.cpp server, and Just the key for a host that does.

The token cap is sent as max_tokens, not as max_completion_tokens, which baikai-openai sends by default and Ollama ignores. The host's other auto-detected quirks are kept. api.openai.com itself keeps max_completion_tokens, because its newer models reject max_tokens.

Custom backends

baikaiBackend :: forall (m :: Type -> Type). MonadIO m => Model -> Options -> Backend m Source #

Build a Backend that makes one baikai-effectful complete call per runBackendChat, against the given Model and base Options. The four constructors of this module are built on it; use it directly for another provider, or for Options they do not set.

The schema of the requested type goes out as the structured-output format on every call, with or without tools, and with strict = True: OpenAI enforces it, and the schema shroom produces already fits OpenAI's strict subset. Anthropic's structured outputs enforce the schema either way.

No synchronous exception a complete call throws escapes this function; it comes back as BackendTransportError. Asynchronous exceptions (SomeAsyncException: a System.Timeout.timeout, ThreadKilled, an async cancellation) propagate, so that a timeout around a hung call returns Nothing instead of being retried as a backend error.

Auxiliary definitions and utilities

normaliseOllamaHost :: Text -> Text Source #

Add a scheme and a default port to an OLLAMA_HOST-style value that lacks them.

Ollama's convention is a bare host or host:port. A value without "scheme://" gets http:// in front, and :11434 behind when it names no port. A value with a scheme is returned as it is, port included, so that https://tunnel-host stays on port 443.

>>> normaliseOllamaHost "gpu-box"
"http://gpu-box:11434"
>>> normaliseOllamaHost "gpu-box:8080"
"http://gpu-box:8080"
>>> normaliseOllamaHost "https://tunnel-host"
"https://tunnel-host"
