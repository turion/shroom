Description

A tool is a Haskell type that the model fills in, together with a ToolHandler that runs it. The type is documented with a Haddock comment, which becomes the description the model reads. A program lists the tools it may call in its constraints, Tool MySearch :> es, offers them to the model with toolBinding and promptTools, and is run with runTool supplying the handler:

-- | A web search query.
data MySearch = MySearch { query :: Text }
  deriving (Generic, ToJSON, FromJSON, ToSchema, SOP.Generic, SOP.HasDatatypeInfo)

$(deriveDescribable ''MySearch)
instance Surveyable MySearch

instance Toolable MySearch where
  toolDescription _ = Just "Returns results from the search API."

mySearchHandler :: ToolHandler MySearch
mySearchHandler = ToolHandler $ \(MySearch q) -> callSearchAPI q

myProgram :: (Tool MySearch :> es, Prompt :> es) => Eff es Result
myProgram = promptTools [toolBinding @MySearch]

result <- runPromptResultEff backend defaultPromptConfig (runTool mySearchHandler myProgram)

Control.Monad.Prompt.Tool.Web provides ready-made tools for fetching pages and searching.

Defining a tool

class (Surveyable t, ToSchema t, FromJSON t, Typeable t) => Toolable t where Source #

A type whose values the model supplies as the input of a tool call.

The model is told the tool's name (toolName), a description made of describeType followed by toolDescription, and the JSON schema of t. When it calls the tool, the input is parsed as t and passed to a ToolHandler, whose result is sent back to the model.

Handling a tool

newtype ToolHandler t Source #

The code that runs tool t: it receives the parsed input and returns Left with a failure message or Right with a result, either of which is sent back to the model. A failure does not count against the limit on tool rounds.

Tools as effects

data Tool t (a :: Type -> Type) b where Source #

The effect of calling tool t.

A program that calls a tool has Tool t :> es in its constraints, and calling it without that constraint does not type-check. A sub-program that needs only some tools runs unchanged inside a program that has more. runTool interprets the effect with a ToolHandler.

Offer tool t to a prompt call. It needs Tool t :> es, so a program can only offer a tool it has been given. The name and description are those of toolDefsRaw.

dispatchBindings :: Applicative m => [ToolBinding m] -> Text -> Value -> m (Either Text Text) Source #

Call the tool of the given name, from a list of bindings, on a JSON input. An unknown name gives a Left that lists the available tools.

The lookup by name happens at run time, since the model sends only a name.
