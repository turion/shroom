Description

Prompt a type part by part, after choosing its constructor if it has several, by deriving Promptable via Generically.

A flat Promptable asks for the whole value in one request. The strategy here instead asks for a record's fields one at a time, each seeing the earlier ones, so that the parts of a value that must fit together (a musician and the city they are from) are built in one train of thought. It then asks the model to improve the assembled value.

The example needs the packages shroom, generics-sop, aeson, openapi3 and text, and the GHC flag -haddock for the module that declares the types: the descriptions are read from their Haddock comments (see Data.Shroom.Class.TH). A leaf type that a field uses is derived before the type that has the field.

{-# LANGUAGE DeriveAnyClass #-}
{-# LANGUAGE DeriveGeneric #-}
{-# LANGUAGE DerivingStrategies #-}
{-# LANGUAGE DerivingVia #-}
{-# LANGUAGE ImportQualifiedPost #-}
{-# LANGUAGE StandaloneDeriving #-}
{-# LANGUAGE TemplateHaskell #-}
{-# LANGUAGE TypeApplications #-}

import Data.Aeson (FromJSON, ToJSON)
import Data.OpenApi (ToSchema)
import Data.Text (Text)
import GHC.Generics (Generic, Generically (..))
import Generics.SOP qualified as SOP

import Control.Monad.Prompt
import Data.Shroom.Class
import Data.Shroom.Class.TH (deriveDescribable)

-- | The name of a city.
newtype City = City Text
  deriving stock (Generic)
  deriving anyclass (ToJSON, FromJSON, ToSchema, SOP.Generic, SOP.HasDatatypeInfo)

$(deriveDescribable ''City)

instance Surveyable City

-- A leaf is flat: one request.
instance Promptable City

-- | A musician.
data Musician = Musician
  { name :: Text
  -- ^ The musician's full name.
  , city :: City
  -- ^ The city the musician is from.
  }
  deriving stock (Generic)
  deriving anyclass (ToJSON, FromJSON, ToSchema, SOP.Generic, SOP.HasDatatypeInfo)

$(deriveDescribable ''Musician)

instance Surveyable Musician

deriving via Generically Musician instance Promptable Musician

A program then asks for a musician with prompt @Musician, as for any Promptable type. A sum is derived the same way; its strategy first asks which constructor to build.

Only the class method prompt runs the strategy, directly or through the instance of a field. The flat promptSingle and improve send one request for the whole value and never run it.

The strategy

prompt for Generically a builds an a in the following steps, all inside one snapshot of the context:

  1. Only for a type with several constructors: the model is told it is about to build a value of a, described by description, and is asked for a ConstructorChoice, an enum of the constructor names.
  2. Unless the constructor has no fields: the model is asked for a Cue, a short, specific steer that every field will follow: a tone or a setting that the first field's request would otherwise leave to chance, and the later ones inherit.
  3. For each field in order, a message names the field (a record's field name, otherwise the constructor's name and the field's position), and the field type's own prompt is called. Its answer stays in the context, so each field sees the earlier ones.
  4. The fields are assembled into a draft and go through improve, which checks it against the type's own Property (see Surveyable) and either keeps it or returns a corrected one.
  5. The context is restored to the snapshot, and one AssistantMessage holding the final value's JSON is appended, as after a flat prompt.

Note that a field type whose own prompt scopes its context leaves no answer behind; the strategy then appends the answer, whenever the context did not grow or does not end in an AssistantMessage. It cannot tell whether a trailing AssistantMessage really is the field's answer, so an override that drops its answer yet appends some other AssistantMessage last goes unnoticed.

Cost

A record with n > 0 fields costs n + 2 requests (cue, fields, improve), where a flat request costs 1: the Musician above costs 4. A constructor of a type with several constructors costs one more for the choice, and one more for every retry. Derive the leaves flat, with a bare instance Promptable, as asking for a scalar part by part would pay a cue and an improve for nothing; use Generically for the records and sums whose parts must cohere.

What the strategy does not do

A field of type [a], NonEmpty a, Set a or Maybe a is prompted whole, in one request for the container, and the properties of its elements are neither checked nor told to the model, as for any container field (see Data.Shroom.Class). A recursive type needs the opt-out that Data.Shroom.Class describes. Anthropic's structured outputs do not support recursive schemas, so such a type fails against Claude even with it.

The schema that improve sends for a sum is the one schemaWithDefs builds from its ToSchema: normalised for structured outputs, so that its oneOf becomes anyOf, and self-contained.

data ConstructorChoice a Source #

The constructor of an a to build, one of the constructors of a. When building an a part by part, the model is asked for it first, and only for a type with several constructors.

On the wire it is a string, one of the constructor names, and nothing else is accepted; its schema is a string enum named after a, so the choices of two sum types do not collide.
