Control.Monad.Prompt.FileMock

Description

fileMockBackend is a Backend that prints the prompt of each request and answers it with the next numbered JSON file (response-001.json, response-002.json, …) instead of calling a model. It shows exactly what is sent for each step, lets you edit the replies to try other scenarios, and costs nothing.

cfg <- defaultFileMockConfig
result <- runPromptResultEff (fileMockBackend cfg) defaultPromptConfig (prompt @User)

Here User is any Promptable type, for example the one in Control.Monad.Prompt. Each file holds the JSON that a model would answer with for that step.

Fields

  • responseDir :: FilePath

    Directory holding the numbered response files. The default is dev/mock-responses/ in the data directory of shroom (getDataDir of the Cabal-generated Paths_shroom), so it does not depend on the current working directory. Set it to read your own files.

  • promptLogFn :: Text -> IO ()

    Called before each reply with the full prompt text (context followed by the type description). The default prints it to stdout.

  • stepCounter :: IORef Int

    Counts the replies given so far, so that the next request reads the next file. defaultFileMockConfig creates it at zero.

defaultFileMockConfig :: IO FileMockConfig Source #

A FileMockConfig that reads the files in dev/mock-responses/ of the shroom data directory and prints prompts to stdout.

fileMockBackend :: forall (m :: Type -> Type). MonadIO m => FileMockConfig -> Backend m Source #

The Backend for a FileMockConfig. It ignores the offered tools, so every reply is a BackendAnswer, and it answers a missing response file with BackendTransportError.
