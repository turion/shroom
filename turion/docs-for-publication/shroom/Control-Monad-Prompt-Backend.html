Description

A Backend makes one raw chat call: it takes the conversation so far, the description and JSON schema of the expected result type and the tools on offer, and returns a BackendReply or a BackendError. The retry and tool loop around that call is in runPrompt.

A Backend is a plain record, not a type class, so building one needs no instance and no dependency on shroom's other modules. An adapter can turn a ToSchema instance into the schema the call needs with schemaWithDefs. fileMockBackend replays canned responses from files; the shroom-baikai package builds a Backend for real models.

constantBackend :: (Applicative m) => Text -> Backend m
constantBackend answer = Backend $ \_ _ _ _ -> pure (Right (BackendAnswer answer))

Backends

newtype Backend (m :: Type -> Type) Source #

A chat backend, reduced to the one call every backend must make. The arguments of runBackendChat are:

  • the conversation so far,
  • the description of the expected result type, appended as the final turn,
  • the JSON schema the response must satisfy,
  • the tools on offer for this call; empty means none.

Contract: an implementation must not throw IO exceptions; every failure comes back as a BackendError.

data BackendReply Source #

The reply of one Backend call: the model's final answer, or the tool calls it wants made before it answers. A backend without tools, such as a mock, always returns BackendAnswer.

Constructors

BackendAnswer Text

The model's final response text, still raw JSON.

BackendToolCalls [ToolCall]

The model wants these tool calls made before it will answer. More than one call means parallel tool calls: dispatch each, then send all the results back together on the next runBackendChat call.

data BackendError Source #

Why a Backend call failed. The three cases are handled differently when retrying: a refusal is terminal, a truncated reply is retried with a request for a shorter one, and a transport failure is retried unchanged.

Constructors

BackendRefusal

The model declined to answer at all; no re-prompt fixes that.

Fields

  • refusalCategory :: Maybe Text

    The category the provider names for the refusal, if it names one.

  • refusalMessage :: Text

    The provider's own message text, for logging.

BackendTruncated Text

The reply was cut off by a length limit and is, at best, half a JSON document. Carries the text that arrived, for logging only.

BackendTransportError Text

Anything else: an HTTP failure, a decode failure, a timeout.

data ContextItem Source #

One item of the conversation history. A Backend maps each item to the message of its transport that has the matching role.

Constructors

SystemMessage Text

Instructions or persona, sent before any user turns.

UserMessage Text

A user turn in the conversation.

AssistantMessage Text

A previous model response. Appended after each successful request so that later prompts can refer to earlier answers.

ToolCallMessage [ToolCall]

The tool calls the model requested in one turn. Parallel calls travel together, so they replay as one assistant turn.

ToolResultMessage [ToolResult]

The results of dispatching the calls of a ToolCallMessage, one per call, each linked to its call by toolResultId.

Schemas

schemaWithDefs :: ToSchema a => Proxy a -> Value Source #

Build the JSON schema of type a, self-contained with no $ref or $defs left in it. It takes the schema openapi3 derives, normalises it for structured-output use and then inlines every reference.

A backend uses it to describe the expected result type and a tool's input to the model.
