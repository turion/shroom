Description

Describable gives a type a one-sentence description and lists the types it refers to. Surveyable builds on it with properties that a value of the type must satisfy, and with example values. description renders a type from both for a model; the shroom package checks the model's answer against the properties. This package is pure: it depends on no HTTP client and no effect system. Promptable, which turns a Surveyable type into a prompt, is in the shroom package, as Control.Monad.Prompt.Promptable.

A bare Surveyable instance surveys the type's fields: the properties of every field's own type become properties of the whole value. For a user type this takes a description derived from the Haddock comments (see Data.Shroom.Class.TH), the generics-sop classes, and an empty instance:

-- | A user with a name and an email address.
data User = User { userName :: Text, userEmail :: Text }
  deriving stock (Generic)
  deriving anyclass (ToJSON, FromJSON, ToSchema, SOP.Generic, SOP.HasDatatypeInfo)

$(deriveDescribable ''User)

instance Surveyable User

Here SOP is Generics.SOP. A type with properties of its own, or none at all, names a Property type instead, see Surveyable.

The classes

class (ToJSON a, Typeable a) => Describable a where Source #

Attach a one-sentence description to a type.

Use $(deriveDescribable ''MyType) from Data.Shroom.Class.TH to derive this from the Haddock comments on the type declaration.

Typeable is a superclass so that description can tell types apart when it lists each reachable type once.

What reaches the model

description sends the requested type's own describeType, and then, in a section of their own, the describeType of every type it can reach through referencedTypes, each once. deriveDescribable writes referencedTypes for you. A hand-written instance that does not write it contributes no reachable types: the types it refers to are not described to the model.

Methods

describeType :: Proxy a -> Text Source #

A one- or two-sentence description of what the type represents, and what the constructors and fields mean.

referencedTypes :: Proxy a -> [Described] Source #

The types whose descriptions the model also needs in order to produce an a: typically the types of its fields. description follows these transitively and lists each type once, so an entry may refer back to the type itself or to another entry without harm.

Build an entry for a field type t with reach @t, which takes the container and base types out and passes their elements through. Defaults to the empty list.

hasOwnSection :: Proxy a -> Bool Source #

Whether the type gets a section of its own in the list of reachable types. Defaults to True. The base types (Text, Int, …) and the containers ([a], Maybe, …) set it to False: they need no section, as their describeType is a sentence that the types using them already quote.

describedIdentity :: Proxy a -> TypeRep Source #

The identity of the type that description reports on, by which reachableTypes keeps that type out of its own list of reachable types. Defaults to the type's own TypeRep. A transparent wrapper (Generically X, DescriptionPrompt X) forwards to the wrapped type's, because description runs at the wrapper while the types that refer back to X name X itself.

Writing a transparent wrapper

A transparent wrapper W a stands for a without being a type of its own to the model. Its Describable instance must forward describeType, and the three methods beyond it:

  • referencedTypes forwards to a's (referencedTypes _ = referencedTypes (Proxy @a)), not reach @a, which would list a under itself;
  • hasOwnSection is False, so the wrapper gets no section;
  • describedIdentity forwards to a's. Forget this one and reachableTypes lists the requested type under itself.

Generically a in this module is such a wrapper, and so is DescriptionPrompt a in the module Control.Monad.Prompt.Promptable of the shroom package.

class (Describable a, Universe (Property a)) => Surveyable a where Source #

Attach properties and example values to a type.

A property is a statement about a value that the model is told and that is checked on the parsed answer. This is the main user-filled class, and a bare instance Surveyable X needs no method: the properties of X are those of its fields. The sections below say what each choice of Property type means.

The default: the properties of the fields

Property defaults to Structural X, and propertyHolds and describeProperties default to structuralHolds and describeStructural. So in

data Booking = Booking { bookingGuest :: Guest, bookingNights :: Int }
  deriving stock (Generic)
  deriving anyclass (ToJSON, FromJSON, ToSchema, SOP.Generic, SOP.HasDatatypeInfo)

instance Surveyable Booking

every property of Guest is a property of Booking: it is described in the prompt (as Field bookingGuest: …) and checked on the parsed value. The default needs the generics-sop classes SOP.Generic and SOP.HasDatatypeInfo for the type, both derivable (deriving anyclass) from Generic of GHC.Generics, and a Surveyable instance for every field type; Text, the number types, Bool, Char, UTCTime and Day have them here.

Opting out: type Property X = Void

A type that wants no properties — a base type, a type whose fields are not Surveyable, or one that does not want the generics-sop instances — writes

instance Surveyable X where
  type Property X = Void

and nothing else: propertyHolds and describeProperties are then filled in (vacuously) as well.

A custom Property replaces the default

Naming a Property type of your own, say type Property X = XProperty, replaces the default entirely: the properties of the fields are neither described nor checked. (A Slot with a Talk field and a property of its own loses the Talk's properties this way.) A custom Property also needs both propertyHolds and describeProperties written out; leaving one out is a compile error naming PropertyDefault (No instance for ‘PropertyDefault XProperty X’), not a silent default of True or Nothing.

To keep the properties of the fields next to your own, combine the two with Either and hand the structural half to structuralHolds and describeStructural:

instance Surveyable X where
  type Property X = Either XProperty (Structural X)
  propertyHolds x (Left p) = … -- the type's own properties
  propertyHolds x (Right p) = structuralHolds x p
  describeProperties px (Left p) = …
  describeProperties px (Right p) = describeStructural px p

All four equations are needed, or the instance is an incomplete pattern match.

Container fields contribute no properties

A field of type [a], NonEmpty a, Set a or Maybe a has no properties of its own (its Property is Void), whatever a has. So under a bare instance the properties of the elements of a [Speaker] or of a Maybe Name field are neither checked nor told to the model. Lift them by hand with everyHolds and describeEvery in a custom Property, as the Speakers example under everyHolds does: it combines the type's own property with the element's property. Add a Structural X half, as above, only where the properties of the type's own fields are wanted too.

Recursive types

A type that is directly or mutually recursive must not use the structural default. "Directly recursive" means a field of its own type that is not under a list, NonEmpty or Maybe, like the Neg Expr in data Expr = Lit Int | Neg Expr; "mutually recursive" means the same through another type's bare instance. Enumerating the structural Property (its Universe) of such a type never ends, and description and violatedProperties (from the shroom package) enumerate it, so with a bare instance Surveyable Expr they do not terminate. Opt out on the recursive type with type Property Expr = Void, or give it a custom Property that does not contain Structural Expr.

A field of a type you do not own

A bare instance fails with an All2 Surveyable error if one of the fields has no Describable and Surveyable instance, as happens for a field of a third-party type. Either opt out on the enclosing type, or give the field type — or a newtype around it, to avoid an orphan instance — its own instances.

Structural properties: the default

data Structural a Source #

The properties of a type that follow from its structure: a property of one field of one constructor, which is a property of the field's own type.

A Structural value picks a constructor of a, then one of that constructor's fields, then one of the properties of the field's type. It is the default Property of Surveyable, where its use and requirements are explained. It is a newtype, not a type family, so that naming it as a Property needs no UndecidableInstances in the user's module.

Its Universe lists every field property of every constructor, in constructor and then field order. A constructor without fields, and a field whose own Property is empty, contribute nothing.

structuralHolds :: (Generic a, All2 Surveyable (Code a)) => a -> Structural a -> Bool Source #

Check a structural property of a value.

A property of constructor c, field f holds vacuously (as in everyHolds) for a value built with a different constructor than c. For a value built with c, it holds exactly when the field's own propertyHolds does.

describeStructural :: (HasDatatypeInfo a, All2 Surveyable (Code a)) => Proxy a -> Structural a -> Maybe Text Source #

Describe a structural property: the field's own describeProperties, prefixed with where it lives.

  • A record field is named Field lastName: …, a positional one by its position and constructor, Field 2 of Pair: ….
  • For a type with several constructors, the constructor is named as well: Constructor FruitApple, field kernels: … or Constructor FruitBanana, field 1: ….

Nothing exactly when the field's own description of the property is.

Helpers for hand-written instances

data Described Source #

A type of which only the Describable instance is known, to put types of different kinds into one list: what referencedTypes returns.

Constructors

Describable t => Described (Proxy t)

Packs the type behind the Proxy, together with its Describable instance.

reach :: Describable t => [Described] Source #

The entries a field of type t contributes to referencedTypes: t itself if it has a section of its own (hasOwnSection), otherwise whatever t itself references. So a field of type [Speaker] or Maybe Speaker contributes Speaker, and a field of type Text contributes nothing:

referencedTypes _ = reach @Person <> reach @[Address] <> reach @Text

reachableTypes :: Describable a => Proxy a -> [Described] Source #

Every type reachable from a through referencedTypes that has a section, see description.

everyHolds :: (Foldable f, Surveyable a) => f a -> Property a -> Bool Source #

Check that one of an element type's properties holds for every element of a container. Use it to lift the element's properties into the container's own Property type, as one side of an Either:

instance Surveyable Speakers where
  type Property Speakers = Either SpeakersProperty SpeakerProperty
  propertyHolds s (Left SpeakersBetween3And10) = ...
  propertyHolds s (Right p) = everyHolds (speakers s) p
  describeProperties _ (Left SpeakersBetween3And10) = ...
  describeProperties _ (Right p) = describeEvery "Every speaker" (Proxy @Speaker) p

In the type Property instance, name the element's concrete property type (here SpeakerProperty) rather than writing Property Speaker: GHC rejects the latter without UndecidableInstances, as a type family application is no smaller than the instance's own left-hand side.

The elements of a container are otherwise neither described nor checked, see Surveyable. Vacuously True for an empty container.

describeEvery :: Surveyable a => Text -> Proxy a -> Property a -> Maybe Text Source #

Describe an element's property as a property of every element of a container, to be used from describeProperties alongside everyHolds. The label is joined to the element's own description with a colon, e.g. describeEvery "Every speaker" turns "The speaker's last name must not be empty." into "Every speaker: The speaker's last name must not be empty.".

Returns Nothing when the element has no description for the property. See everyHolds for the pattern.

Rendering a type for the model

description :: (Surveyable a, ToSchema a) => Proxy a -> Text Source #

Render a type for the model: its description, its properties and its example values, if any.

The text goes to the model next to the JSON schema; runPrompt (from the shroom package) sends it as the prompt text. Field descriptions are annotated with their JSON types, see annotateFieldTypes.

After the examples comes a section with the describeType of every type the requested type reaches through referencedTypes, see Describable. Each type is listed once, told apart by its TypeRep (so Choice Fuel and Choice Phase are two types), breadth first and in the order referencedTypes lists them, and never the requested type itself, also when it is recursive. The section is absent when nothing is reachable.

annotateFieldTypes :: Value -> Text -> Text Source #

Annotate each field line of a type description with its JSON type.

For each line - fieldName: doc in the description, look up fieldName in the OpenAPI schema's properties map and insert the JSON type in parentheses: - fieldName (string): doc. Lines that do not match the pattern or lack a known type are left unchanged.
