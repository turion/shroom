Control.Monad.Prompt.Promptable

Description

The Promptable typeclass: defines the default way to request a value of a type from an LLM backend.

class (Surveyable a, ToSchema a, FromJSON a) => Promptable a where
  prompt :: forall es. (Prompt :> es, State [ContextItem] :> es) => Eff es a
  prompt = Effect.promptSingle

The default prompt is promptSingle: it sends a RequestPrompt effect, which uses description to build the prompt text from the type's Surveyable metadata.

Override prompt to add type-specific context, fallback logic, or any other custom program. The method has State [ContextItem] in scope, so an override can scope context with withContext:

instance Promptable MyType where
  prompt = withContext "Always prefer metric units." Effect.promptSingle

Typical usage (no override needed):

$(deriveDescribable ''MyType)

instance Surveyable MyType where ...

instance Promptable MyType

Pure/effectful boundary

This module is the effectful side of the line drawn against Data.Shroom.Class, and the package boundary coincides with it: Data.Shroom.Class lives in shroom-class, this module in shroom. Promptable's method is an Eff program requiring the Prompt effect, so anything that names Promptable or DescriptionPrompt depends on the program layer and must live under Control.Monad.Prompt, never under Data.Shroom.. Nothing under Data.Shroom. may import this module.

class (Surveyable a, ToSchema a, FromJSON a) => Promptable a where Source #

Attach a default prompting strategy to a type.

The single method prompt is an Eff program that requests a value of type a from the LLM. The default implementation sends RequestPrompt, which builds the prompt from description (the type description, properties, and examples from the Surveyable instance).

Superclasses: Surveyable, ToSchema, FromJSON.

An Eff program that requests a value of type a from the LLM.

Override to add type-specific context, fallback logic, parallel sub-prompts, or any other custom behaviour. The State [ContextItem] constraint is what lets an override scope context with withContext or withContextItem; it is the same state context adds to, so a caller that already chains prompts has it.

Promptable Text Source #

Flat Promptable instances for the base types that Data.Shroom.Class gives Surveyable instances: Text, Int, Integer, Int64, Word, Natural, Double, Float, Bool, Char, UTCTime, Day, and the containers [a], NonEmpty a, Set a and Maybe a. Each uses the default prompt, so a bare value is requested like any other type, from its description.

They live in this module, next to the class, so they are not orphans.

Schema keywords Anthropic rejects. openapi3 renders some of these types with JSON Schema keywords that Anthropic's structured outputs answer with a 400, and that normalizeSchemaForStructuredOutput does not strip: Char carries minLength and maxLength, Natural carries exclusiveMinimum, and Double and Float carry a numeric format (not confirmed against the API). A field of one of these types, or a bare prompt of it, may therefore fail against Claude until the normaliser strips those keywords. The container instances pass the element's schema through unchanged, so they inherit the same limitation.

(Surveyable a, ToSchema a, FromJSON a, ToJSON (Generically a), FromJSON (Generically a), Generic a, HasDatatypeInfo a, All2 Promptable (Code a)) => Promptable (Generically a) Source #

Orphan. It cannot sit next to the class in Control.Monad.Prompt.Promptable: the strategy calls that class's own prompt on every field and improve from Control.Monad.Prompt.Effect, and keeping the strategy in a module of its own is worth one orphan. Describable and Surveyable for Generically are not orphans: they are in Data.Shroom.Class.

The method is what deriving via coerces; the context is mostly about a, and ToJSON (Generically a) and FromJSON (Generically a) are aeson's generic ones, needed by the superclasses.
