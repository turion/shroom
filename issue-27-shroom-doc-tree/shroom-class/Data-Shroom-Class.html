Data.Shroom.Class

Description

The Describable and Surveyable typeclasses: attach a human-readable description, properties, and example values to a type, so that an LLM backend — or anything else that renders a type for a reader, human or model — can understand what it should produce.

Typeclass hierarchy

Describable          — describeType: one sentence from Haddock (auto-derived)
    └── Surveyable   — Property, propertyHolds, describeProperties, examples
                       (by default the properties of the type's own fields, see below)

Promptable, which builds on Surveyable to render a full prompt, lives on the far side of the pure/effectful boundary — in the shroom package, as Control.Monad.Prompt.Promptable — see below.

Typical usage. A bare Surveyable instance surveys the type's fields: the properties of every field's own type become properties of the whole value (see Structural). It needs the generics-sop classes SOP.Generic and SOP.HasDatatypeInfo (with import qualified Generics.SOP as SOP, and generics-sop among the package's build-depends):

-- | A user with a name and an email address.
data User = User { userName :: Text, userEmail :: Text }
  deriving stock (Generic)
  deriving anyclass (ToJSON, FromJSON, ToSchema, SOP.Generic, SOP.HasDatatypeInfo)

$(deriveDescribable ''User)   -- generates instance Describable User from Haddock

instance Surveyable User      -- the properties of Text fields: there are none

instance Promptable User  -- from Control.Monad.Prompt.Promptable; uses the
                          -- default description-based prompt rendering

A type that has properties of its own states them instead, and then needs both propertyHolds and describeProperties:

instance Surveyable User where
  type Property User = UserProperty
  propertyHolds u UserEmailNotEmpty = not (T.null (userEmail u))
  describeProperties _ UserEmailNotEmpty = Just "The email must not be empty."

To keep the field properties alongside its own, combine the two with Either (all four equations are needed). Writing this by hand is interim: a derived "Combined" property source is planned in issue #18. See the Surveyable Haddock for details:

instance Surveyable User where
  type Property User = Either UserProperty (Structural User)
  propertyHolds u (Left p) = … -- the type's own properties
  propertyHolds u (Right p) = structuralHolds u p
  describeProperties pu (Left p) = …
  describeProperties pu (Right p) = describeStructural pu p

A type that wants no properties at all, and no generics-sop instances, opts out in one line, with no methods:

instance Surveyable User where
  type Property User = Void

Pure/effectful boundary

This module is pure, and the package boundary coincides with that line: it lives in shroom-class, which has no program layer, while everything effectful lives in shroom. It depends only on aeson, text, containers, openapi3, universe-base, generics-sop and time, and nothing under Data.Shroom. may import Control.Monad.Prompt or any of its submodules. That is deliberate, not incidental — a later arc (shroom-shikumi, C3) needs exactly this pure half, with no program layer attached, to feed shikumi's own instruction and validation machinery. Keep it that way: an import of Control.Monad.Prompt here would put the program layer back in C3's way.

annotateFieldTypes :: Value -> Text -> Text Source #

For each "- fieldName: doc" line in the type description, look up fieldName in the OpenAPI schema's properties map and insert the JSON type in parentheses: "- fieldName (string): doc". Lines that don't match the pattern or lack a known type are left unchanged.

describeConstructor :: forall (xss :: [[Type]]). All2 Surveyable xss => Bool -> NP ConstructorInfo xss -> NS (NS PropertyOf) xss -> Maybe Text Source #

describeEvery :: Surveyable a => Text -> Proxy a -> Property a -> Maybe Text Source #

Describe an element's property as a property of every element of a container, to be used from describeProperties alongside everyHolds. The label is joined to the element's own description with a colon, e.g. describeEvery "Every speaker" turns "The speaker's last name must not be empty." into "Every speaker: The speaker's last name must not be empty.".

Returns Nothing when the element has no description for the property. See everyHolds for the pattern, and issue #18 for the derivable version.

describeStructural :: (HasDatatypeInfo a, All2 Surveyable (Code a)) => Proxy a -> Structural a -> Maybe Text Source #

Describe a structural property: the field's own describeProperties, prefixed with where it lives.

  • A record field is named Field lastName: …, a positional one by its position and constructor, Field 2 of Pair: ….
  • For a type with several constructors, the constructor is named as well: Constructor FruitApple, field kernels: … or Constructor FruitBanana, field 1: ….

Nothing exactly when the field's own description of the property is.

description :: (Surveyable a, ToSchema a) => Proxy a -> Text Source #

Render the full prompt fragment for a type: its description, any properties, and example values (if any).

This is what gets sent to the LLM alongside the JSON schema. Field descriptions are annotated with their JSON types from the OpenAPI schema (e.g. - name (string): The user's full name.).

This is what runPrompt (from the shroom package) sends as the prompt text for a RequestPrompt.

After the examples comes a section of the types the requested type refers to, through referencedTypes: each such type once (told apart by its TypeRep, so Choice Fuel and Choice Phase are two types), breadth first from the requested type and in the order referencedTypes lists them, never the requested type itself, and also for recursive types. Each entry is the type's name and its describeType, nothing more. The section is absent when nothing is reachable, so a type without references renders as before. Types with hasOwnSection False (the base types and the containers) get no entry, and a hand-written instance that does not write referencedTypes contributes none.

everyHolds :: (Foldable f, Surveyable a) => f a -> Property a -> Bool Source #

Check that one of an element type's properties holds for every element of a container. Use it to lift the element's properties into the container's own Property type, as one side of an Either:

instance Surveyable Speakers where
  type Property Speakers = Either SpeakersProperty SpeakerProperty
  propertyHolds s (Left SpeakersBetween3And10) = ...
  propertyHolds s (Right p) = everyHolds (speakers s) p
  describeProperties _ (Left SpeakersBetween3And10) = ...
  describeProperties _ (Right p) = describeEvery "Every speaker" (Proxy @Speaker) p

Name the element's concrete property type (here SpeakerProperty) rather than writing Property Speaker in the instance head: GHC rejects the latter without UndecidableInstances, as a type family application is no smaller than the instance's own left-hand side.

runPrompt (from the shroom package) only checks the properties of the top-level value, and description only lists those, so without this lift a property of the elements is neither told to the model nor checked. This is a hand-written helper; a derivable version is tracked in issue #18.

Vacuously True for an empty container.

reach :: Describable t => [Described] Source #

The entries a field of type t contributes to referencedTypes: t itself if it has a section of its own (hasOwnSection), otherwise whatever t itself references. So a field of type [Speaker] or Maybe Speaker contributes Speaker, and a field of type Text contributes nothing:

referencedTypes _ = reach @Person <> reach @[Address] <> reach @Text

reachableTypes :: Describable a => Proxy a -> [Described] Source #

Every type reachable from a through referencedTypes that has a section, see description.

structuralHolds :: (Generic a, All2 Surveyable (Code a)) => a -> Structural a -> Bool Source #

Check a structural property of a value.

A property of constructor c, field f holds vacuously (as in everyHolds) for a value built with a different constructor than c. For a value built with c, it holds exactly when the field's own propertyHolds does.

class (ToJSON a, Typeable a) => Describable a where Source #

Attach a one-sentence description to a type.

Minimal complete definition: describeType.

Use $(deriveDescribable ''MyType) from Control.Monad.Prompt.TH to derive this automatically from all Haddock comments on the type declaration.

Typeable is a superclass so that description can tell types apart when it lists each reachable type once (see referencedTypes). Every concrete type is Typeable automatically, and a polymorphic instance gets it from the Describable context of its type parameter, so no instance needs to change.

What reaches the model

description sends the requested type's own describeType, and then, in a section of their own, the describeType of every type it can reach through referencedTypes, each once. A type that wants its field types documented to the model lists them in referencedTypes; deriveDescribable does this for you. __A hand-written instance that does not write referencedTypes contributes no reachable types__: the types it refers to are not described to the model.

Methods

describeType :: Proxy a -> Text Source #

A one- or two-sentence description of what the type represents, and what the constructors and fields mean.

referencedTypes :: Proxy a -> [Described] Source #

The types whose descriptions the model also needs in order to produce an a: typically the types of its fields. description follows these transitively and lists each type once, so an entry may refer back to the type itself or to another entry without harm.

Build an entry for a field type t with reach @t, which takes the container and base types out and passes their elements through. Defaults to the empty list, so a hand-written instance that does not write this method contributes no reachable types.

hasOwnSection :: Proxy a -> Bool Source #

Whether the type gets a section of its own in the list of reachable types. Defaults to True, so a hand-written instance is listed. The base types (Text, Int, …) and the containers ([a], Maybe, …) set it to False: they need no section, as their describeType is a sentence that the types using them already quote.

describedIdentity :: Proxy a -> TypeRep Source #

The identity of the type that description reports on, by which reachableTypes keeps that type out of its own list of reachable types. Defaults to the type's own TypeRep. A transparent wrapper (Generically X, DescriptionPrompt X) forwards to the wrapped type's, because description runs at the wrapper while the types that refer back to X name X itself.

Writing a transparent wrapper

A transparent wrapper W a stands for a without being a type of its own to the model. Its Describable instance must forward describeType, and the three methods beyond it:

  • referencedTypes forwards to a's (referencedTypes _ = referencedTypes (Proxy @a)), not reach @a, which would list a under itself;
  • hasOwnSection is False, so the wrapper gets no section;
  • describedIdentity forwards to a's. Forget this one and reachableTypes lists the requested type under itself.

There are two such wrappers: Generically a in this module, and DescriptionPrompt a in Control.Monad.Prompt.Promptable of the shroom package. Keep the two in step.

newtype Structural a Source #

The properties of a type that follow from its structure: a property of one field of one constructor, which is a property of the field's own type.

A Structural value picks a constructor of a, then one of that constructor's fields, then one of the field type's own Propertys. A type whose fields are all Surveyable can use it as its own Property type without writing out any property:

instance Surveyable Person where
  type Property Person = Structural Person
  propertyHolds = structuralHolds
  describeProperties = describeStructural

(For this the type needs the generics-sop classes Generic and HasDatatypeInfo, both derivable from GHC.Generics's own Generic.)

A bare instance Surveyable Person now does exactly this by default, so the explicit form above is only needed when spelling it out, for example as the Right half of an Either (see Surveyable).

It is a newtype, not a type family, so that naming it as a Property needs no UndecidableInstances in the user's module.

Its Universe lists every field property of every constructor, in constructor and then field order. A constructor without fields, and a field whose own Property is empty, contribute nothing.

class (Describable a, Universe (Property a)) => Surveyable a where Source #

Attach properties and example values to a type.

This is the main user-filled class. A bare instance Surveyable X needs no method at all: the type's properties are those of its fields, see below.

Superclass: Describable.

The default: the properties of the fields

Property defaults to Structural X, and propertyHolds and describeProperties default to structuralHolds and describeStructural. So in

data Booking = Booking { bookingGuest :: Guest, bookingNights :: Int }
  deriving stock (Generic)
  deriving anyclass (ToJSON, FromJSON, ToSchema, SOP.Generic, SOP.HasDatatypeInfo)

instance Surveyable Booking

every property of Guest is a property of Booking: it is described in the prompt (as Field bookingGuest: …) and checked on the parsed value. The default needs the generics-sop classes SOP.Generic and SOP.HasDatatypeInfo for the type, both derivable (deriving anyclass) from GHC.Generics's Generic, and a Surveyable instance for every field type; Text, the number types, Bool, Char, UTCTime and Day have them here.

Opting out: type Property X = Void

A type that wants no properties — a base type, a type whose fields are not Surveyable, or one that simply does not want the generics-sop instances — writes

instance Surveyable X where
  type Property X = Void

and nothing else: propertyHolds and describeProperties are then filled in (vacuously) as well.

A custom Property replaces the default

Naming a Property type of your own, say type Property X = XProperty, replaces the default entirely: the properties of the fields are neither described nor checked any more. (A Slot with a Talk field and a property of its own loses the Talk's properties this way.) A custom Property also needs both propertyHolds and describeProperties written out; leaving one out is a compile error (No instance for ‘PropertyDefault XProperty X’ arising from a use of ‘Data.Shroom.Class.$dmdescribeProperties’, see PropertyDefault), not a silent default of True or Nothing.

To keep the properties of the fields next to your own, combine the two with Either and hand the structural half to structuralHolds and describeStructural:

instance Surveyable X where
  type Property X = Either XProperty (Structural X)
  propertyHolds x (Left p) = … -- the type's own properties
  propertyHolds x (Right p) = structuralHolds x p
  describeProperties px (Left p) = …
  describeProperties px (Right p) = describeStructural px p

All four equations are needed, or the instance is an incomplete pattern match. Writing this combination by hand is interim: a derived "Combined" property source, which adds a type's own properties to its structural ones, is planned in issue #18.

Container fields contribute no properties

A field of type [a], NonEmpty a, Set a or Maybe a has no properties of its own (its Property is Void), whatever a has. So under a bare instance the properties of the elements of a [Speaker] or of a Maybe Name field stay unchecked, and not even told to the model, until container lifting (issue #18) is derivable. For now lift them by hand with everyHolds and describeEvery in a custom Property combined with Structural X, as the Speakers example under everyHolds does.

A recursive type with a bare instance hangs

A type that is directly or mutually recursive must not use the structural default. "Directly recursive" means a field of its own type that is not under a list, NonEmpty or Maybe, like the Neg Expr in data Expr = Lit Int | Neg Expr; "mutually recursive" means the same through another type's bare instance. Enumerating the structural Property (its Universe) of such a type never ends, and description and violatedProperties (in shroom) enumerate it, so with a bare instance Surveyable Expr they run forever, in shroom before any request is sent and on every backend. (Under the former Void default this worked.) Opt out on the recursive type with type Property Expr = Void, as above, or give it a custom Property that does not contain Structural Expr.

A field of a type you do not own

A bare instance fails with an All2 Surveyable error if one of the fields has no Describable and Surveyable instance, as happens for a field of a third-party type. Either write the opt-out above on the enclosing type, or give the field type — or a newtype around it, to avoid an orphan instance — its own instances.

type Property a Source #

The type of properties for a. Must have a Universe instance. Defaults to Structural a, the properties of a's fields; write type Property a = Void for no properties at all.

type Property a = Structural a

propertyHolds :: a -> Property a -> Bool Source #

Check whether the property holds.

Returns True if the property holds for the value, False if it is violated. Used for validation after parsing.

Defaults to checking the Structural properties of the fields if Property is its default, and to nothing at all if it is Void. For any other Property there is no default, and the method must be written.

Hint: If you have an "informal" property (like "is an english name") that can't be easily checked with code, you can still include it in describeProperties and return True here.

Human-readable description of a property, used in the prompt. May be Nothing if you don't wish to describe it.
