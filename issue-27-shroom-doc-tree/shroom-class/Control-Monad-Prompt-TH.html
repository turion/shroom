deriveDescribable :: Name -> Q [Dec] Source #

Generate a complete Describable instance for a type, deriving describeType from its Haddock documentation comment and referencedTypes from its fields. Use this when you don't need to customise the description:

-- | A user with a name and an email address.
data User = User { userName :: Text, userEmail :: Text }

$(deriveDescribable ''User)

This generates:

instance Describable User where
  describeType = _ -> pack "A user with a name and an email address.\n..."
  referencedTypes _ = reach @Text <> (reach @Text <> mempty)

referencedTypes is the concatenation, in declaration order, of reach @t for the type t of every field of every constructor, record and positional alike. So the types of the fields reach the model through description: each is described once, in a section after the examples, however often and however deeply it is used.

Every field type must have a Describable instance, from an earlier splice or the same one; a field type without one is a compile-time error ("No instance for Describable …"). Splice order therefore matters. Mutually recursive types are derived in a single splice, $(concat <$> traverse deriveDescribable [''A, ''B]); a self-recursive type needs nothing special.

A parameterised type derives too, with one Describable a constraint for each type variable of kind Type:

-- | One of two alternatives.
data Choice a = Pick a | Skip

$(deriveDescribable ''Choice)

generates instance (Describable a) => Describable (Choice a), where a field of type a contributes reach @a, so that Choice Fuel makes Fuel reachable.

A type variable of any other kind (a Symbol or Nat unit, a dimension, or an unannotated phantom parameter, which GHC2024 makes poly-kinded) can never be the type of a field, so it needs no Describable. It is annotated with its kind in the instance head and needs only Typeable, as does each kind variable its kind mentions:

-- | An amount in some unit.
newtype Measure (unit :: Symbol) = Measure Double

-- | A value tagged by a phantom parameter.
newtype Tagged a = Tagged Double

$(deriveDescribable ''Measure)
$(deriveDescribable ''Tagged)

generates instance Typeable unit => Describable (Measure (unit :: Symbol)) and instance (Typeable k, Typeable a) => Describable (Tagged (a :: k)). The generated code uses type applications and the instance head's type variables, so the module needs TypeApplications and ScopedTypeVariables (both in GHC2021 and GHC2024).

To override describeType manually, write the Describable instance by hand. You can use deriveDescribableExp for the body, and modify it as needed, but then also write referencedTypes.

instance Describable MyType where
  describeType = $(deriveDescribableExp ''MyType)
  referencedTypes _ = reach @Inner

This requires the module to be compiled with the -haddock GHC flag, which is set automatically when using this package's build configuration.

Error: A compile-time error is raised if no Haddock documentation is found.

deriveDescribableExp :: Name -> Q Exp Source #

Produce the describeType method body for a type, using its Haddock documentation comment. Use this inside a manually written Describable instance:

instance Describable MyType where
  describeType = $(deriveDescribableExp ''MyType)
  referencedTypes _ = reach @Inner

This returns the describeType body only. It does not collect the referenced types: a hand-written instance must write referencedTypes itself, or its field types are not described to the model. For a wrapper that is referencedTypes _ = reach @a; for a record, the reach @t of each of its field types, as deriveDescribable generates.

For a type with several constructors, each constructor is listed as - Constructor: doc (by name alone if undocumented), followed by its documented fields indented beneath it. For a single-constructor type, the constructor's own doc, if any, is a line of its own right after the type's doc, and the documented fields are listed directly. A documented record field is listed as - fieldName: doc, a documented positional field as - field N: doc with N counting from 1; an undocumented field adds nothing.

Which Haddock layout documents what, for a constructor with positional fields (GHC's rule for H98 constructors):

data Shape
  = -- | Documents the constructor Circle.
    Circle Double
  | Square Double -- ^ Documents the constructor Square, not its argument.
  | -- | Documents the constructor Rect.
    Rect
      Double
      -- ^ Documents the first argument of Rect.
      Double
      -- ^ Documents the second argument of Rect.

A one-line trailing comment after the constructor and all its arguments, as on Square, documents the constructor (it renders as - Square: doc). A positional argument's doc is collected only when the constructor has a leading Haddock comment or each argument stands on a line of its own with its own trailing comment, as on Rect, which renders its two arguments as - field 1: … and - field 2: …. An argument documented in any other way is not collected, because GHC does not attach the comment to the argument. A leading comment on each argument (a Haddock comment on the line above the argument's type) is collected the same way; this is the layout that fourmolu rewrites the trailing comments into, and it renders unchanged.

Prefer deriveDescribable for the common case where a full instance is needed.
